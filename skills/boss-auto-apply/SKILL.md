# Boss Auto Apply — BOSS直聘自动投递

## 免责声明

- 本项目仅供学习交流使用。
- 使用者自行承担使用本项目的一切后果与责任，作者不对任何使用行为负责。
- 注意：自动化操作可能触发目标平台的风控机制，导致账号被临时停用或功能受限。

## 定位

本 skill 提供**动手能力**，不做决策。agent 负责全部判断（解析简历、判断岗位合适度、筛选、节奏、记录），skill 只提供两个动作脚本。

## 提供的动作

### 1. 搜索岗位

```bash
python3 scripts/search_jobs.py --keyword <岗位关键词> --city <城市> [--page N] [--output jobs.json]
```

- 用 CloakBrowser 打开 BOSS 搜索页，抓取岗位卡片，输出 JSON 列表
- 每个岗位含：`id`（详情页 ID）、`title`（岗位名）、`company`（公司名）、`salary`（薪资）、`href`
- 首次使用需扫码登录（登录态自动持久化在 `data/browser_profile/`）

### 2. 点击「立即沟通」

```bash
python3 scripts/apply_action.py --job-id <id> [--applied data/applied.md]
```

- 跳转岗位详情页，真实点击「立即沟通」（BOSS 自动带上默认招呼语）
- 脚本强制约束（安全底线，agent 不可跳过）：
  - **每日 150 硬顶**：投递前检查 `data/applied.md` 今日条数，达到则拒绝
  - **风控即停**：检测到风控信号（code 37 / 环境异常 / 操作过于频繁）则停止并返回原因
- 返回结果：`{'ok': bool, 'reason': str}`。`ok=false` 时 agent 需根据 `reason` 处理（硬顶→停止、风控→通知用户、按钮缺失→视觉兜底）

## Agent 工作流程（agent 自主决策）

### 1. 理解需求
- 询问/确认用户：简历位置、期望岗位、城市、薪资、类型（实习/全职）、黑名单、投递数量上限等

### 2. 解析简历（自由发挥，无脚本）
- 简历格式多样（docx / pdf / 扫描件 / 图片），自行选择合适方式：
  - docx：用 python-docx 或直接读文本
  - PDF：先尝试文本提取（如 PyMuPDF / pdftotext）；**提取不出文字（扫描件/图片型 PDF）用视觉读图解析**
- 将结构化结果（姓名/技能/经验/期望）记录到 `data/resume.md`，供后续判断

### 3. 建立偏好档案（agent 维护，无脚本）
- 用 `data/profile.md` 长期记录用户偏好：期望岗位/城市/薪资/类型/黑名单/备注
- 用 Read/Edit 直接维护该文件；对话中用户的新要求随时追加
- 每次会话先读 `data/profile.md`，避免重复询问

### 4. 搜索岗位
- 按偏好关键词+城市执行 `search_jobs.py`，输出岗位列表

### 5. 筛选与判断（agent 自主）
- 对每个岗位，结合用户需求、简历、偏好档案判断是否合适：
  - 岗位职责/要求与技能匹配度
  - 薪资范围、城市、公司、类型是否符合偏好
  - 黑名单公司/岗位排除
- **判断是 agent 的责任**，不依赖任何脚本规则

### 6. 投递
- 对判断合适的岗位，逐个执行 `apply_action.py --job-id <id>`
- 控制节奏：每岗位之间间隔数秒（拟人化，避免过密），数量到用户上限或 150 硬顶即停
- 处理脚本返回：硬顶→停止告知用户；风控→立即停止通知用户，不得重试

### 7. 记录（agent 负责）
每次投递后，**必须**把投递记录追加到 `data/applied.md`，一行一条：

```markdown
2026-07-31 10:23 job_id=12345 状态=成功 备注=字节跳动 Python后端
```

- 必要字段：日期、时间、job_id、状态（成功/失败/风控暂停/硬顶）
- **用户要求的其他信息**：用户想记什么（公司、岗位、备注、HR 信息……）都追加到该行
- 投递前可读 `applied.md` 判断：今日已投几条、某 job_id 是否已投过（去重）

### 8. 收尾
- 向用户汇报：投递数量、成功/失败明细、风控情况、下一步建议

## 风控即停（agent 必须遵守）

- 脚本返回风控信号 / 页面出现「环境存在异常」「安全验证」「操作过于频繁」→ **立即停止**，通知用户人工判断，不得重试
- 验证码/滑块出现 → 暂停，通知用户人工处理，完成后恢复
- 登录页跳转 → 提示用户扫码登录（cookie 约 7 天过期）

## 选择器

页面选择器集中管理在 `references/selectors.md`。改版失效时只改该文件（控制层），脚本逻辑不动。若某选择器失效（脚本报找不到元素），可用视觉兜底（截图观察）临时定位，但必须随后更新 selectors.md。

## 视觉兜底流程

1. 脚本报错（找不到元素）时，截图观察页面结构：`page.screenshot(path="data/debug.png")`
2. 从截图中识别目标元素新位置，用视觉定位完成该次操作
3. 必须随后更新 `references/selectors.md`，记录新选择器
